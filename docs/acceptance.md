# 인수 기준과 검증 범위

## 로컬 자동 검증

`pytest -q` 51개, `scripts/browser_check.py` 1회로 다음을 확인합니다.

- 계정: 가입 코드 검증(오답·빈값 거절), 아이디/비밀번호/이름 형식 검증, 중복 아이디 거절, 첫 계정 관리자 승격, 로그인 실패 5회 후 잠금, 로그아웃 후 재접근 차단, 비로그인 API 401.
- 예약 소유권: 본인 예약만 수정·취소, 관리자는 전체 관리, 예약자 이름·아이디가 세션 계정과 일치.
- 모니터링 미연동 상태: 오프라인 장애와 구분해 표시하고, 사용률·리포트는 503으로 알리며 `/metrics`에 값을 내보내지 않음.
- GPU 상태 8종, 예약 API 장애/메트릭 단절/수집 불완전 시 보수적 상태 처리.
- 멀티 GPU 예약 원자적 저장, 중첩 거절, 경계가 맞닿는 예약 허용, 동시 요청 충돌 처리.
- 잘못된 GPU/시간/음수 자원/장기 예약 사유 검증.
- 타인 예약 수정·취소 거절, cross-origin 쓰기 차단, live 모드 데모 API 차단.
- 실제 API 문서 형태의 LibreBooking 인증 헤더·예약 목록·멀티 GPU 그룹화 계약 테스트.
- GPU 프로세스의 Linux 사용자·PID·VRAM 조인, 오래된 표본 제외.
- Prometheus 리포트 계약: 표본 수 → GPU-hour 환산, 수집률, 예약 중 사용 비율, KST 시간대별 포화 집계.
- 알림 판정: 대여 사용, 예약 시작 직후 타 사용자 사용, 예약 종료 후 사용 지속(2시간 이내), 오프라인/확인 필요, 정상 시 무알림.
- `/metrics`의 `lab_gpu_reserved` · `lab_gpu_reserved_busy` · `lab_gpu_busy` · `lab_gpu_borrowed` 노출과 UNKNOWN/OFFLINE 제외.
- Chromium에서 회원가입(잘못된 코드 거절 포함)·로그인·로그아웃·재로그인 후 예약 유지, 데스크톱/모바일, 메뉴·필터·예약 생성/수정/새로고침 유지/취소, 운영 리포트 7일/30일 전환, 알림 목록, JavaScript 오류 검사.
- Compose 설정 해석과 Grafana JSON/Prometheus rules YAML 구문 확인.

## 실제 장비에서 완료해야 하는 항목

| 원문 항목 | 완료 기준 | 현재 상태 |
|---|---|---|
| T1 단일 예약 | 학생 계정으로 실제 GPU 2시간 예약 | 포털에서 자동 검증 완료, 실제 장비 확인 필요 |
| T2 멀티 GPU | 여러 GPU가 한 예약으로 표시 | 자동 검증 완료, 실제 장비 확인 필요 |
| T3 예약 없는 학습 | 실행 차단 없이 Busy 상태와 실사용자 표시 | 수집기 코드 완료, GPU 실행 확인 필요 |
| T4 Reserved idle | 예약+idle 확인 후 Borrowable | 판정 테스트 완료, exporter 연동 필요 |
| T5 GPU 서버 재부팅 | exporter DOWN 후 UP 및 상태 복구 | 현장 확인 필요 |
| T6 NAS 재부팅 | 모든 중앙 컨테이너 자동 복구 | 현장 확인 필요 |
| T7 포트 접근 제한 | NAS만 9100/9400 접근 가능 | 실제 네트워크 확인 필요 |
| T8 백업 복구 | 계정·예약 DB 복원 | 절차 작성, 현장 확인 필요 |

실제 장비 정보가 없는 상태에서 위 항목을 완료로 표시하지 않습니다. Docker 엔진이 실행되지 않은 개발 PC에서 컨테이너 이미지 pull/build 및 전체 서비스 기동을 검증했다고 주장하지 않습니다. 장애 훈련 절차는 [장애 대응](troubleshooting.md)에 있습니다.

## 확장 항목(원문 17장) 현황

| 항목 | 상태 |
|---|---|
| GPU별 7/30일 평균 utilization | 운영 리포트와 Grafana 기록 규칙으로 제공 |
| 서버별 GPU idle 시간 | 운영 리포트의 서버별 유휴/실사용 GPU-h |
| 예약된 시간 대비 실제 Busy 시간 | 모니터링 화면(24시간/7일)과 운영 리포트(7일/30일) |
| 학생별 GPU-hour | 예약 GPU-h와 프로세스 수집 기반 실사용 GPU-h를 함께 표시. 수집기 설치 후부터 집계 |
| 멀티 GPU 작업 비율 | 운영 리포트 기간 요약 |
| CPU/RAM 포화 시간대 | 서버별 24시간 프로파일과 포화(기본 85% 이상) 시간 |
| GPU 서버 Offline/온도/XID 알림 | Prometheus rules (5분·30분 지속 포함) |
| 예약 시간에 다른 사용자 Busy | 화면 알림 + `ReservedGPUUsedByOthers` 규칙(10분) |
| 장기 예약 종료 후 미연장 | 화면 알림(예약 종료 후 2시간 이내 동일 사용자 실행 중) |
| 외부 메신저/메일 알림 | 미구현. 수신처와 Alertmanager/Grafana contact point를 운영자가 지정해야 합니다 |

수치는 Prometheus 보관 기간(기본 30일)과 포털 연동 시작 이후만 반영합니다. 모르는 구간은 표본에서 제외하고 수집률을 함께 표시하며, 유휴 0%로 채우지 않습니다. 이 통계는 학생 평가가 아니라 증설·재배치 판단용입니다.

GPU 강제 할당, queue, preemption, Slurm/Kubernetes, 자동 kill은 의도적으로 구현하지 않습니다.
